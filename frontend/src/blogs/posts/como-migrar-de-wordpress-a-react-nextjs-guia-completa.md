Migrar de WordPress a React/Next.js es una de las mejores decisiones técnicas que podés tomar para tu negocio. Pero si se hace mal, podés perder meses de posicionamiento SEO en Google de la noche a la mañana.

---

## ¿Por qué migrar de WordPress?

1. **Seguridad**: WordPress recibe el 90% de los ciberataques a CMS. Los plugins desactualizados son la puerta de entrada #1.
2. **Velocidad**: Un WordPress con 15 plugins activos tarda 3-5 segundos en cargar. Next.js carga en sub-segundo.
3. **Costo de mantenimiento**: Plugins premium ($50-200 USD/año cada uno), hosting más potente, actualizaciones constantes.
4. **Limitaciones de diseño**: Con WordPress dependés de las opciones del theme. Con React, el diseño es 100% libre.

---

## Plan de Migración en 5 Fases

### Fase 1: Auditoría del sitio actual
- Listar todas las URLs existentes con tráfico orgánico (Google Search Console → Rendimiento → Páginas).
- Exportar la base de datos de contenido (posts, páginas, categorías, media).
- Documentar las redirecciones existentes.

### Fase 2: Mapeo de URLs (CRÍTICO para SEO)
Cada URL de WordPress debe tener una correspondencia exacta en el nuevo sitio:
- `/2024/01/mi-articulo/` → `/blog/mi-articulo`
- Crear redirecciones 301 permanentes para TODAS las URLs que cambien.

### Fase 3: Desarrollo del nuevo sitio en Next.js
- Replicar toda la estructura de contenido.
- Implementar SSR/SSG para SEO perfecto.
- Mantener los mismos meta tags (title, description) en cada página.
- Integrar Google Analytics y Search Console desde el día 1.

### Fase 4: Testing de SEO pre-lanzamiento
- Verificar que el sitemap.xml incluya TODAS las URLs.
- Verificar que robots.txt no bloquee nada.
- Ejecutar Screaming Frog para detectar errores 404.
- Comparar PageSpeed antes vs. después.

### Fase 5: Lanzamiento y monitoreo
- Activar las redirecciones 301.
- Enviar el nuevo sitemap a Google Search Console.
- Monitorear impresiones y clics durante 30 días.
- Si alguna URL pierde posición, verificar la redirección.
