**Para pasar de Excel a un sistema sin frenar la empresa, el orden es: entender qué hace hoy cada planilla, limpiar y estandarizar los datos, elegir o desarrollar el sistema, migrar por módulos (por ejemplo, primero clientes y stock, después facturación) y hacer convivir el sistema nuevo con la planilla durante un período de control.** El error más caro es migrar todo de golpe con datos desordenados.

En esta guía verás cuándo Excel deja de alcanzar, cómo planificar la migración paso a paso, cómo limpiar los datos, qué hacer con un sistema viejo (legacy) que todavía funciona y cómo evitar que el equipo vuelva a la planilla.

## Cuándo Excel deja de alcanzar

| Señal | Riesgo |
| --- | --- |
| Varias personas editan la misma planilla | Versiones distintas, datos pisados |
| Hay copias por sucursal o por vendedor | Nadie tiene la información completa |
| Las fórmulas las entiende una sola persona | Si se va, nadie sabe cómo funciona |
| Se tarda horas en armar un reporte | Decisiones tarde o sin datos |
| Hay errores de stock, precios o facturación | Pérdidas directas |
| No hay historial de quién cambió qué | Sin control ni auditoría |

Excel es una gran herramienta para analizar datos; no está hecha para ser el sistema operativo de una empresa con varios usuarios.

## Paso a paso para migrar

### 1. Haz un inventario de planillas

Lista cada planilla: para qué sirve, quién la usa, cada cuánto se actualiza y de dónde salen sus datos. Muchas veces aparecen planillas que nadie usa y otras críticas que dependen de una sola persona.

### 2. Dibuja el proceso real

Cómo entra un pedido, quién lo carga, cómo se descuenta el stock, cómo se factura. La migración es la oportunidad de corregir pasos innecesarios.

### 3. Limpia los datos

- Elimina duplicados (el mismo cliente escrito de tres formas).
- Unifica formatos: fechas, teléfonos, códigos de producto.
- Completa los datos faltantes que el sistema nuevo va a necesitar.
- Define un código único por cliente y por producto.

### 4. Elige el sistema

Un sistema estándar si tu proceso es común; uno a medida si es propio o necesitas integraciones específicas. Ver [CRM a medida](/blog/por-que-tu-empresa-necesita-un-crm-erp-a-medida).

### 5. Migra por módulos

Empieza por el módulo que más duele y menos riesgo tiene. Un orden habitual: clientes y productos, después stock, después ventas, al final facturación y finanzas.

### 6. Convivencia y control

Durante unas semanas, el sistema nuevo y la planilla funcionan en paralelo. Al final de cada día o semana se comparan los números. Cuando coinciden, se apaga la planilla.

### 7. Capacita y documenta

Cada rol tiene que saber qué cargar, cuándo y dónde. Una guía corta por rol funciona mejor que un manual largo.

## Checklist de datos antes de migrar

| Dato | Qué revisar | Cómo dejarlo listo |
| --- | --- | --- |
| Clientes | Duplicados, CUIT o documento faltante, teléfonos con distintos formatos | Un registro por cliente, documento obligatorio, teléfono con código de país |
| Productos | Nombres distintos para el mismo producto, variantes en columnas | Código único por producto y variante |
| Precios | Listas de precios en varias planillas | Una lista por canal o tipo de cliente, con fecha de vigencia |
| Stock | Conteos viejos | Inventario físico el día de la migración |
| Saldos | Deudas de clientes y con proveedores | Saldo inicial conciliado con la contabilidad |
| Historial | Ventas de años anteriores | Decidir cuánto historial migrar y qué queda como archivo |

## Ejemplo de calendario de migración

Un ejemplo ilustrativo para una distribuidora que hoy trabaja con planillas de clientes, stock y pedidos:

| Semana | Actividad |
| --- | --- |
| 1 | Inventario de planillas y relevamiento del proceso con cada área |
| 2 | Limpieza de clientes y productos; definición de códigos |
| 3 a 6 | Desarrollo o configuración de los módulos de clientes, productos y stock |
| 7 | Inventario físico y carga del stock inicial |
| 8 a 9 | Convivencia: pedidos en el sistema y en la planilla, comparación diaria |
| 10 | Se apaga la planilla de stock; empieza el módulo de facturación |

Cada empresa tiene su ritmo, pero el principio es el mismo: un módulo a la vez, con control antes de avanzar.

## Qué hacer con un sistema viejo (legacy)

Muchas empresas tienen un sistema antiguo (de escritorio, hecho a medida hace años, sin soporte) que todavía funciona. Opciones:

| Opción | Cuándo conviene | Riesgo |
| --- | --- | --- |
| Mantenerlo y conectarlo | Funciona bien y solo falta acceso web o integración | Sigue dependiendo de tecnología vieja |
| Reemplazo gradual por módulos | El sistema es crítico y no puede apagarse de golpe | Convivencia más larga |
| Reemplazo completo | El sistema falla, no tiene soporte o frena el crecimiento | Migración más exigente |

En todos los casos, lo primero es extraer y respaldar los datos, y documentar qué hace el sistema actual, incluidas las reglas "escondidas" que nadie recuerda.

## Cómo evitar que el equipo vuelva a la planilla

- **Involucra a quienes van a usarlo** desde el diseño.
- **Que el sistema sea más rápido** que la planilla para las tareas diarias.
- **Elimina la planilla** después del período de convivencia.
- **Reportes que antes no existían**: cuando el equipo ve el beneficio, adopta el sistema.

## Preguntas frecuentes

### ¿Cómo pasar de Excel a un sistema de gestión?

Inventaria las planillas, dibuja el proceso, limpia los datos, elige el sistema, migra por módulos y haz convivir el sistema con la planilla hasta que los números coincidan.

### ¿Se pueden importar mis planillas al sistema?

Sí, después de limpiarlas: sin duplicados, con formatos unificados y códigos únicos para clientes y productos.

### ¿Cuánto tarda la migración?

Depende de la cantidad de procesos y del estado de los datos. Migrar por módulos permite empezar a usar el sistema en semanas mientras se completa el resto.

### ¿Qué hago si mi sistema actual es muy viejo?

Primero respalda los datos y documenta qué hace. Después decide si conviene conectarlo, reemplazarlo por partes o reemplazarlo completo.

### ¿Pierdo el historial de mis planillas?

No, si se planifica. Se decide qué historial migrar al sistema (por ejemplo, los últimos dos años de ventas) y el resto queda archivado y accesible para consultas.

### ¿Qué pasa si el sistema nuevo falla durante la convivencia?

Para eso existe la convivencia: mientras se comparan resultados, la planilla sigue siendo el respaldo. Se apaga recién cuando los números coinciden durante varias semanas.
